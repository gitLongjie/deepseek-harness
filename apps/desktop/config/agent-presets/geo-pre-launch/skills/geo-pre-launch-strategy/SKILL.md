# GEO 上线前优化策略技能

上线前的 GEO 不是"多写内容"，而是三件事：**判断引擎为什么没有引用这个品牌**、**把品牌事实变成可被引用的证据**、**在有限时间里排出干预顺序**。本技能提供这四步的判定表、字段与模板。

## Step 0 — 前置检查（缺项即停）

必须有：品牌实体信息、竞品 3–5 个及其被引来源、RAG 切片报告、目标引擎清单（国内池/海外池分开）、上线日期与资源。

四问检查，任一为否则停止分析、只输出补采清单：

1. 切片报告有没有**用户问句**？没有 → 无法反推场景词。
2. 有没有**来源 URL**？没有 → 无法判定 E3。
3. 有没有**引擎标识**？没有 → 无法分池。
4. 竞品是否在**同一批问句**上有占位记录？没有 → 优先级无参照。

## Step 1 — 切片诊断：五类失效

对每条切片判定**主失效类型 + 次失效类型**。

| 代码 | 失效类型 | 表现特征 | 对应动作 | 生效周期 |
|---|---|---|---|---|
| **E1** | 实体未识别 Entity Miss | 引擎不知道品牌存在，或认成同名事物/竞品 | 百科条目、官网 About 结构化、工商与商标一致性、别名同义词标注、Wikidata（海外池） | 4–8 周 |
| **E2** | 事实密度不足 Fact Sparsity | 提到品牌，但无可抽取断言（无数字、无时间、无参数、无对比） | 断言化改写：一段一事实，主谓宾+数字+时间，删形容词 | 2–3 周 |
| **E3** | 引用源缺失 Source Gap | 有断言，但只存在于品牌自述页面 | 第三方载体铺设：行业媒体、独立评测、白皮书、问答社区 | 3–6 周 |
| **E4** | 结构不可切 Chunk Hostility | 长段散文、图片内文字、JS 动态渲染、无小标题 | H2 改问句、定义块、对比表、FAQ 与 schema.org、llms.txt | 1–3 周 |
| **E5** | 语义错配 Intent Drift | 有召回但答非所问（答"是什么"，用户问"和谁比"） | 按场景词补比较/避坑/价格/替代四变体 | 1–2 周 |

判定顺序（避免主次颠倒）：

- **E1 互斥优先**：实体没被识别时，其他诊断都不可信，先修 E1 再复测。
- **E4 是隐形放大器**：结构不可切会让 E2/E3 的投入全部打折。看到"有内容但从不被召回"，先怀疑 E4。
- **E2 与 E3 常同时出现**：先做 E2（自己改得动），E3 并行启动（周期长）。
- **E5 只在"有召回但答案跑偏"时成立**，不要拿它解释"根本没被召回"。

每条切片记录：切片 ID、问句、召回来源、引擎、位次、是否提及品牌、可抽取事实数、主/次失效类型、修复动作、修复成本（低/中/高）、生效周期（天）、优先级。

## Step 2 — 证据链：五要素与分级

证据单元（Evidence Unit）五要素，缺一不得进入排期：

1. **断言 Claim** —— 可被单独摘出引用的一句话，含主体、数字或时间、可核对基准。反例："品质卓越、行业领先"。
2. **归属 Attribution** —— 品牌自述 / 第三方机构 / 真实用户。
3. **载体 Carrier** —— 可公开访问 URL + 发布主体 + 发布时间，三者缺一等于没有载体。
4. **可验证性 Verifiability** —— 外部能否独立核对：有原始数据、有测试方法、有对比基准。
5. **时效 Freshness** —— 有效期至哪天、按什么节奏更新（价格类 3 个月、参数类 12 个月、资质类随证件）。

| 等级 | 构成 | 用法 |
|---|---|---|
| **A** | 第三方权威 + 可核对数据 + 近 12 个月内 | 核心断言，直接支撑占位 |
| **B** | 品牌自述 + 可核对数据 | 可投放，须配 A 级背书补强 |
| **C** | 品牌自述 + 无数据 | 仅辅助说明，不得作核心断言 |
| **D** | 无法溯源、转载套娃、无发布主体 | 禁用，进黑名单 |

红线：一条断言只挂一个主载体；同一断言不得同日多渠道群发（同源同文是操纵信号）；不得制造无出处的"行业第一/唯一/领先"；医疗/金融/教育/功效类断言必须过合规审；载体里没有的数字不得出现在断言里。

## Step 3 — 场景词矩阵

三层结构：**L1 品类词**（`XX 是什么` / `XX 哪个好`）→ **L2 场景词**（`给【人群】做【任务】时选什么`）→ **L3 长尾问句**（必须覆盖**比较、避坑、价格、替代**四类变体）。

字段：层级、词/问句、意图类型（认知/比较/决策/排障）、引擎池、目标引擎、当前占位（有/无/竞品占）、竞争强度（1–5）、意图价值（1–5）、缺口系数（1–3）、修复成本（1–5）、优先级分、对应证据 ID、真实问法来源。

```
优先级分 = 意图价值 × 缺口系数 ÷ 修复成本      # 保留一位小数，降序排
```

引擎分层（必须分表，禁止混排）：

| 维度 | 国内池（豆包/元宝/Kimi/DeepSeek） | 海外池（ChatGPT Search/Perplexity/Gemini） |
|---|---|---|
| 主要语料来源 | 公众号、知乎、小红书、头条、百科、B 站 | 官网可抓取文本、Wikipedia/Wikidata、Reddit、独立评测站、GitHub |
| 可干预面 | 内容平台账号矩阵 + 百科词条 | 官网结构 + llms.txt + schema.org + 第三方评测与社区 |
| 内容形态偏好 | 中文长文、问答体、经验叙述 | 结构化定义、对比表、可引用数据、英文实体页 |
| 生效节奏 | 2–4 周 | 4–8 周 |
| 常见坑 | 只在自有官网发，平台不收录 | 官网 JS 渲染，爬虫读不到正文 |

## Step 4 — 投放排期（地基先行）

| 窗口 | 阶段 | 核心动作 | 为什么在这个位置 |
|---|---|---|---|
| T-8 ~ T-6 周 | 打地基 | E1 实体底座 + E4 结构化重排 | 后续内容全靠它被检索到；顺序颠倒等于白做 |
| T-6 ~ T-4 周 | 建证据 | A 级第三方载体铺设 + E2 断言化改写 | 周期最长，必须最早并行 |
| T-4 ~ T-2 周 | 铺场景 | L3 问句集中发布，同渠道间隔 ≥3 天 | 留出索引与复测时间 |
| T-2 ~ T-0 周 | 补位 | 未占位引擎定向补 + 全池交叉复测 | 上线前最后一轮校准 |
| T-0 之后 | 交接 | 转入监测（不在本技能范围） | — |

排期字段：周次、阶段、动作、对应失效类型、渠道/载体、责任方、产出物、**验收标准（可测）**、依赖、状态。

验收标准反例："完成官网优化"。正例："官网页面前 200 字内 ≥5 条含数字断言；H2 全为问句；FAQ schema 校验通过；目标问句在 Kimi 复测中进入召回前 5"。

## 输出模板（固定四段式）

1. **诊断结论** —— 按 E1–E5 聚合，每类给切片 ID 清单 + 一句话归因 + 修复方向。
2. **证据链台账** —— 表格 + A/B/C/D 等级分布 + 明确写出"当前最高能支撑到什么强度"。
3. **场景词矩阵** —— 国内池 / 海外池两张表，按优先级分降序。
4. **排期表 + 风险与前置依赖** —— 含"某项前置缺失会让哪一段排期整体顺延"。

## 交付前自检（六条）

- 每条策略能否对应**具体切片 ID**？不能 → 删。
- 每条断言是否挂到**可访问 URL**？挂不上 → 降级或撤。
- 每个场景词是否有**真实问法来源**？编的 → 删。
- 排期是否**地基先行**（E1/E4 在前两周）？
- 国内池与海外池是否**分表**？
- 合规敏感断言是否**标注并过审**？

## 拒绝条件

- 无切片报告 → 只输出补采字段清单，不出策略。
- 无第三方渠道可动用 → 明确告知"最高只能到 B 级证据，占位上限约 30–40%"，由客户决定是否调资源。
- 要求承诺排名或曝光 → 拒绝，并解释 GEO 的作用机制是"提高被引用概率"，不是"锁定位置"。
