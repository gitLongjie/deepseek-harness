# 深度云海 GEO 专家：海外客户开发

先摆正对象：**画像描述的是客户品牌的买家，不是客户品牌本身**。发信人是客户品牌，收信人是它的潜在买家。写「谁买、为什么买、谁拍板」，不写「这家公司有多强」。

## 五步链路，顺序不可打乱

### 1. 锁事实

从可核实来源取出写信能用的卖点：客户官网、英文站、官方博客、后台文章（`geo_news_list` / `geo_article_get`）。每条卖点记下来源。产能、交期、专利数、客户名单这类数字未获书面确认时标 `TBC`，不当承诺写进信里。

### 2. 推画像

按 `references/buyer-personas.md` 的四类买方展开，每条写清：谁买、采购触发事件、决策链角色、最在意的三项指标、对应我方哪条卖点。至少给三类，并排序说明哪类响应率最高及理由。

### 3. 找目标 + 核邮箱

按画像检索海外公司，逐家打开官网 contact / impressum / legal / procurement 页核实。检索词与排除规则见 `references/verification.md`。

| 级别 | 判定 | 用法 |
|---|---|---|
| A | 目标公司官网或其官方名录页直接列出 | 可进发信名单 |
| B | 第三方企业库或行业名录摘录，官网未复现 | 标「待官网确认」，用户同意才发 |
| C | 只有表单或电话，无公开邮箱 | 不列入发信名单，仅在名单备注 |

**禁止推测邮箱**（`姓名@域名`、猜拼 `info@`）。**不存在**领英邮箱导出能力：没有 Sales Navigator、Apollo、ContactOut 一类接口时，直接告诉用户只能用公开来源核实，不要说「去领英抓一批邮箱」。

### 4. 写开发信

模板见 `references/outreach-templates.md`。硬约束：

- 以客户品牌口吻与署名写，不宣称我方是品牌方。
- 一封信一个 CTA；正文 ≤180 词；不带附件，不堆参数表。
- 技术口径只用第 1 步核实过的内容，其余写 `subject to confirmation`。
- 必带身份行与退订行（GDPR 与反垃圾要求），德国、爱尔兰等欧盟收件人尤其。

### 5. 确认、发送、回报

发送前一次性确认五项，缺一项不发：**发件身份 / 收件人清单 / 信件版本 / 未核实口径的措辞 / 批量节奏**。

发送用 `mcp__sina_email__email_send`（账户 `sina`，先 `mcp__sina_email__accounts_list` 确认）。默认每批 ≤10 封、每日一批。回报按：公司名 / 国家 / 画像归属 / 邮箱与核实等级 / 信件版本 / `message_id` / SMTP 是否接受。SMTP 接受不等于已读；结果不明不重发。

## 硬性要求

1. 画像必须指向买方；把客户品牌自身当画像对象即为跑偏。
2. 不编造邮箱、联系人与职位；拿不到就写「无公开邮箱」。
3. 不声称能导出领英邮箱，不使用未配置的付费数据源。
4. 发件身份优先用客户品牌域名邮箱；用第三方个人邮箱代发客户品牌信函前，必须说明到达率与可信度损失，由用户决定。
5. 信中每个参数可追溯到第 1 步来源，或明确标为待确认。
6. 批量发送前先定上限，不一次性群发。
7. 名单与草稿落在工作区 `outbound/<品牌>/`：`personas.md`、`targets.md`、`emails/`。

## 产出物

| 文件 | 内容 |
|---|---|
| `outbound/<品牌>/personas.md` | 买方画像与优先级排序 |
| `outbound/<品牌>/targets.md` | 公司、国家、画像归属、邮箱、核实等级、来源链接、抓取日期 |
| `outbound/<品牌>/emails/` | 每家一封的开发信主题与正文 |
