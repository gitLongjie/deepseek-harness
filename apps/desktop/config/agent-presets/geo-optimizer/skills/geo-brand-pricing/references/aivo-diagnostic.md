# AIVO 可见度诊断协议

AIVO（AI Visibility Optimization）诊断回答一个问题：当用户在 AI 搜索里问品类问题时，目标品牌出现的频率和位置。诊断产出当前可见度 V0，是整个报价的锚点。

## 1. 设计探测集

从客户的关键词/品类出发，构造 10–20 条「真实买家会问 AI 的问题」，三类各占约三分之一：

- 品类词：「办公协作工具推荐」「敏感肌精华哪个牌子好」
- 品牌词：「{品牌} 怎么样」「{品牌} 和 {竞品} 哪个好」
- 场景长尾：「小团队远程办公用什么软件」

问题集写进诊断报告，报价争议时可复测。

## 2. 按引擎探测

按客户市场选引擎，国内默认：豆包、Kimi、DeepSeek、腾讯元宝、文心一言、通义千问；国际默认：ChatGPT、Perplexity、Gemini、Copilot、Claude。

每条问题在每个引擎下记录：

| 字段 | 说明 |
|------|------|
| 是否出现 | 品牌是否出现在回答中 |
| 位置 | 首推 / 列表内 / 未出现 |
| 是否被引用 | 品牌域名是否作为来源被引用（影响 V 的加权） |
| 情感 | 正面 / 中性 / 负面 |

探测手段按可用性降级，用了哪档写进报告：

1. 引擎官方 API / 可直连的对话接口——直问探测集问题。
2. WebSearch 检索「site:引擎域名 品牌」「引擎 品牌 推荐」等间接证据。
3. 客户提供的后台数据或第三方监测截图。

某引擎三档都不可用时，把它从加权中剔除并标注「抽样受限」，不要用想象补数。

## 3. 计算 V0

```
V_e = 100 × (出现且被引用 × 1.0 + 出现未引用 × 0.5) / 该引擎探测样本数
V0  = Σ w_e × V_e        # w_e 为引擎权重，默认均分，客户指定主攻引擎时加权
```

分档（用于话术和目标建议，不直接进公式）：

| V0 | 等级 | 建议目标 |
|----|------|----------|
| < 20 | 严重缺失 | 先做到 40 |
| 20–40 | 起步 | 冲 55–65 |
| 40–60 | 中等 | 冲 70–80 |
| 60–80 | 良好 | 冲 85+ |
| 80+ | 领先 | 保位 + 负面防御 |

## 4. 竞品基准

对 2–3 个主要竞品跑同一探测集，得出竞品 V0 区间。用途：校准 k_comp、让客户目标有参照。竞品探测可以只抽样 5 条问题（减半成本），但要标注抽样子集。

## 5. 诊断报告结构

```markdown
## AIVO 诊断摘要 — {品牌}（{日期}）
- V0 = {分数}（{等级}），主攻引擎 V_e：{逐引擎列出}
- 探测集：{N} 条，见附表；引擎覆盖：{可用/受限各哪些}
- 竞品基准：{竞品A} {分数}、{竞品B} {分数}
- 关键缺口：{哪类问题、哪个引擎缺口最大}
```
