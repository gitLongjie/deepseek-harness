# Agent Note: API key 路由不再跟随官方模型列表

Status: implemented

[English](2026-10-22-deepseek-official-model-listing.md) | 中文

## 问题

`deepseek-official` 路由提供的是 `models` 设置里的内容，而这个设置默认是每个构建自带的目录。DeepSeek API 新增的模型只能随发版到达 API key 用户，而账号路由已经在同一个 origin 上跟随服务端的 `GET /models` 列表。与账号路由不同，官方路由的目录可以由用户编辑：模型页把编辑后的目录存进 `models`，`baseURL` 后面的网关也在这里声明自己的模型。

## 决策

API key 路由不请求 `GET /models`。[这一撤回](../simplification/2026-11-04-api-key-route-skips-model-listing.zh.md)取代本记录原先写下的跟随行为。账号路由仍通过共享的 Messages 传输跟随 `GET /models`。

## 考虑过的替代方案

这些替代方案当时让位于跟随列表。该跟随已经撤回；这里保留它们，作为当初如何划定跟随方式的记录。

**在所有端点上跟随列表。** 发布 OpenAI 风格 `/models` 的网关返回的条目没有 `api_capabilities.anthropic_messages`，解码器会隐藏它们，路由就不提供任何模型。每个这样的网关还会多收到一个携带 key 的请求。

**按模型 id 合并自定义目录与列表。** 自定义用户会继续收到新列出的模型，但用户删掉的模型会重新出现，而模型页无法隐藏某一个列出的模型。

**去掉 `models` 的 schema 默认值来标记未设置。** 缺省值不用比较目录就能选中列表，但模型页会失去它显示的继承行；这些行连同隐藏的 `systemPromptUpdate`、`toolUpdate` 字段会被复制进自定义目录。从通用模型发现 API 复制的行会丢掉这些字段。

**每个进程只获取一次，或按定时器刷新。** 只获取一次会让常驻的 Web 或桌面宿主停留在启动时的目录，一次偶发失败就会让它固定在内置目录。定时器会在路由空闲时发请求。由访问触发的后台刷新与账号路由一致。

**恢复默认后沿用缓存的列表。** 缓存可能在 `modelsMaxAgeMs` 内一直提供自定义之前加载的列表；列表请求代价很小，所以恢复默认总是重新加载。重新加载从下一次访问开始，而不是在监听器里进行，这样凭据查询及其失败都留在请求路径上；Web 页面保存后的设置刷新会立即发起这次访问。

## 影响

- API key 用户得到的是配置的目录。服务端之后新增的模型，要等发版更新内置目录，或部署写入 `models`，才会到达。
- 账号路由仍无需发版即可收到列出的模型。它的列表缓存、客户端版本门控和刷新仍在共享传输包中。
- 在官方端点上启动账号路由的测试套件必须自己应答列表请求。API key 路由不发出该请求。
