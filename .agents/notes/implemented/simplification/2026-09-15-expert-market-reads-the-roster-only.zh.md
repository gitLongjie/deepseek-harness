# Agent Note: 专家市场只读部署名单

Status: implemented

[English](2026-09-15-expert-market-reads-the-roster-only.md) | 中文

## Problem

专家市场（`packages/client/ui-expert`）合并两个来源：部署随附的名单行，以及一份写死的精选名单（`mock-data.ts`，十三张专家卡片加四条精选场景横幅，镜像某个参考市场）。每次页面加载都会展示部署从未发行的专家——为仓库里没有任何对应 preset 的第三方产品准备的卡片——而且合并逻辑让写死记录在展示上优先于共享同一 id 的服务器行。部署无法管理市场展示的内容，空的部署也会看到一个满满的市场。

## Decision

市场的唯一来源是部署的 agent-preset 名单：发布了卡片元数据（设置了 `category`——把模式类 preset 挡在外面的已提交专家标记）的行投射为卡片记录，其余来源全部移除。`mock-data.ts` 已删除，精选场景横幅随之删除；横幅所在区块、它的 `featured.title` 词典键与对应 CSS 规则一并移除。名单读取被拒或缺席时降级为空市场，页面渲染既有的空态。

卡片记录设计不变：记录携带 `subtitle`、`badge`、`avatar` 时照常渲染，缺失的行回退到确定性的渐变底色与已发布的字符图标。两个随附专家（`geo-optimizer`、`article-publisher`）的 `preset.yml` 已经发布完整的卡片设计；只有署名副标题、策展徽标与头像图片要等名单携带它们，这一点记录在包 README 的延期工作中。

## Alternatives considered

**保留精选名单作为空名单时的兜底。** 否决：对没有发行任何专家的部署，空市场才是诚实状态；任何残存的兜底都会复活部署无法查看也无法管理的内容——这正是本次删除要消灭的性质。

**把精选卡片移植进随附 `preset.yml` 元数据而不是删除。** 对第三方卡片否决：它们描述的产品在仓库里没有对应 preset，移植等于虚构可部署专家。对两个真实专家无需移植——它们的 `preset.yml` 本就发布卡片展示的全部元数据，名单读取器会投射它。

## Verification

`packages/client/ui-expert/tests/apply.client.spec.tsx` 只放行携带卡片元数据的随附行，并钉住读取被拒时降级为空市场；`browser.client.spec.tsx` 使用自己的夹具，覆盖记录设计、搜索、筛选与聘用。包测试通过（12/12），包类型检查干净，oxlint 干净。

## Consequences

市场展示部署实际发行的内容，没有时明确显示"暂无专家"。精选名单时代的精选场景界面被整体移除——区块、词典键与 CSS。在名单经市场安装通道携带之前，卡片失去写死记录曾有的署名副标题、策展徽标与头像图片；这些字段保留在记录合约中，一旦有值即会渲染。
