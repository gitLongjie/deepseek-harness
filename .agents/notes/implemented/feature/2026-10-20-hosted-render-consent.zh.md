# Agent Note：托管 H3 渲染需要显式确认

Status: implemented

[English](2026-10-20-hosted-render-consent.md) | 中文

## 问题

一份在本地 ComfyUI 后端尚未配置时写下的计划，把 `backend: "remote"` 固化进了每个片段。随后渲染按生成秒数为托管 MiniMax API 计费，而对话里没有任何一处征求过意见；工具结果只回报了调用方请求的标签，于是"这段到底跑在 GPU 上还是付费 API 上"无法从记录里回答。渲染时计划就是权威，所以事后修组合毫无作用：花销已经写进文档了。

## 决定

- `video_plan` 与 `video_render` 拒绝任何有效后端为 `remote` 的批次，除非调用带上 `allow_remote=true`。拒绝信息列出片段与它们的总秒数，让成本成为对话确认过的数量，而不是路由的副作用。计划侧的这半边是关键，因为后续渲染读的就是计划。
- 已提交的片段除 `backend`（调用方要求的策略）之外，回报 `resolved`——实际到达的后端。`auto` 不再隐藏工作去了哪里。
- 守卫不把 `auto` 计入付费。路由在提交时解析它，而"没有配置本地后端"是应当就地表露的配置事实，不是逐次调用的确认问题。

## 考虑过的替代方案

- **只在结果里告警而不拒绝。** 否决：工具返回时任务已经排队，告警到达时钱已经花出去了。
- **把 `auto` 也算作付费。** 否决：路由按请求解析 `auto`，本地后端可用的部署会因为这条把所有计划都拒掉。

## 后果

- 只有远端后端的部署在计划与渲染两处都传 `allow_remote=true`。这份摩擦正是重点：它是花销被确认的唯一位置。
- `resolved` 随结果进入模型与会话日志，回放因此能看到每段实际在何处渲染。

## 验证证据

- 付费渲染在任何东西到达后端之前就被拒绝：没有请求被记录，也没有任务启动。
- 带 `allow_remote=true` 的调用会提交，且每条提交记录回报 `resolved: remote`。
