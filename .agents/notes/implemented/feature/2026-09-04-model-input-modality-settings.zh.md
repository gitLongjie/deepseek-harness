# Agent Note: 模型输入类型设置

Status: implemented

[English](2026-09-04-model-input-modality-settings.md) | 中文

## 问题

LLM 适配器已经暴露输入类型能力，并会拒绝未声明图片输入的模型所收到的图片请求，但模型设置页面无法让用户为已配置模型声明该能力。

## 决策

模型设置编辑器在每个模型行的高级区域提供文本和图片输入选项。文本为必选，图片为可选。pi-ai 编辑器将声明保存为 `input`，直接 DeepSeek 编辑器保存为 `inputModalities`。采用 pi-ai 提供方发现的模型时，会保留提供方返回的输入类型。设置写入前会拒绝未知、重复或不包含文本的声明。

界面只支持当前 LLM 消息和提供方适配器已经承载的类型：文本和图片输入。视频输入与输出类型要等这些层能够端到端传递相应值后再加入。

## 考虑过的替代方案

**添加通用的自由输入类型字段。** 未采用，因为未勾选或拼写错误的值可能声明请求序列化器和提供方并不支持的能力。

**根据模型 ID 或端点推断图片能力。** 未采用，因为命名约定和网关行为都不是权威来源；现有适配器能力字段才是请求时图片闸门使用的来源。

**同时添加视频和输出类型选项。** 未采用，因为当前消息词汇和提供方实现并不携带这些类型。

## 后果

用户无需编辑 `settings.yaml` 即可配置自定义视觉模型，采用模型时也会保留发现到的图片能力。启用图片输入仍然是对端点的声明：如果端点拒绝请求，提供方仍可能返回错误。已有模型和省略输入类型的字段继续使用当前适配器默认值。

## 验证

模型设置客户端测试覆盖 pi-ai 与 DeepSeek 的写入、无效输入类型拒绝、本地化标签及既有模型编辑路径。提供方运行时已有请求时图片能力检查的测试。
