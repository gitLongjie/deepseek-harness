# Agent Note:知识库文档浏览器

Status: implemented

[English](2026-09-08-knowledge-base-document-browser.md) | 中文

## 问题

侧边栏的知识库分区点击即新建会话,用户能说出部署暴露了哪些库,却始终看不到库的内部。腾讯 ima 的资料库页面给出了预期形态:选中一个库,以表格阅读其文档(名称/类型/更新时间),并可搜索。

## 决策

知识库接缝长出 `listDocuments(baseId, query?)`:`dsh-kb-weknora` 经 `GET /knowledge-bases/:id/knowledge` 实现(单页取路由上限,后端关键词过滤),`dsh-kb-gateway` 以 `listDocuments` 动词投影。侧边栏的可折叠库列表由一个知识库入口行取代;点击它在会话区打开完整的知识页面——库列表与文档浏览器(名称/类型/更新时间)并列,带后端过滤的搜索、部署控制台动作,以及每个库的"提问"动作。`UiKnowledgeService` 以 ConversationRoot 上一个 inject-hooks 源持有临时页面状态;任何会话导航都会经会话列表上的侦听器关闭页面——会话表面永远赢得会话区。浏览器头部承载返回、库标题、后端过滤的搜索与"提问"动作;表格渲染标题/种类/扩展名/更新时间。任何会话导航都会经会话列表上的侦听器关闭浏览器——会话表面永远赢得会话区。

响应式源走 ConversationInjected 的 hooks(composerBlock 通道)而非新增 GlobalStandardProps 成员——同样的响应性,不在其他所有插槽组件的测试里激起 props 涟漪。ConversationRoot 把该 hook 视为可选并配了一个无 hook 的替身选择器,因为 ui-knowledge-base 插件是可选挂载。

## 备选方案

**设置页式的全屏浮层。** 否决:盖住整个框架的模态不是参考的 ima 布局——文档表应作为会话的对等面嵌入。

**行上保留会话启动、浏览再次延期。** 否决:用户只能命名库却看不到内部;文档表才是知识库的意义所在。

**一次无过滤拉取后客户端过滤。** 搜索场景否决:后端本就按关键词匹配标题与内容,匹配权在部署而非客户端。

## 后果

文档预览、千条首页之后的分页、存储配额页脚、ima 式的个人/共享分组仍然延期——WeKnora API 不暴露库分组,预览需要文档内容端点。hook 的加入让每个插槽组件测试挂载多了一个 `useKnowledgeView` 桩,与既有标准源的机械代价相同。

## 验证

提供者测试覆盖文档请求形状(页界、编码后的库 id、关键词)、含标题/种类回退的字段映射,以及响亮的契约失败。网关测试覆盖线面投影。浏览器面板测试覆盖状态、搜索、提问与返回。导航/页面注册测试覆盖注入共享、页面状态切换与卸载;骨架测试覆盖页面分支替换会话区及其缺席路径。
