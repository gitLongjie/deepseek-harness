# Agent Note: Separately rendered shots share one look

Status: implemented

[English](2026-10-18-cross-segment-shot-consistency.md) | 中文

## Problem

超过一条 H3 任务的影片只能逐镜头渲染（`per_segment`），而每个镜头都是一次独立生成：模型每次都会重新采样面孔、服装、陈设与光线。多镜头分镜做出来就像若干段互不相关的片段，而不是同一场戏。本该承载一致性的三个机制都没有做到：计划的 `style` 行被存了下来、文档也写着"注入生成 prompt"，但没有任何 prompt 真正收到它；关键帧只按文本生成，于是锚定每段视频的静帧各自发明了一个角色；每次本地提交都重新抽一个随机种子，连重渲染单个镜头都会得到不同的观感。

## Decision

现在由同一个 prompt 组装函数 `segmentPrompt` 产出镜头关键帧与视频片段的文本：镜头文本、运镜说明、每个挂载素材的外貌描述，以及计划的风格行。静帧与片段因此被同样地描述，风格也进入了包括素材图在内的每条生成路径。

素材锚点按镜头匹配。镜头以其 prompt 点名的已锚定素材（真正出现在画面里的角色、场景、道具）为条件；一个都没点名时使用全部锚点，因此从不点名锚点的分镜仍以完整锚点集为条件。每个挂上的锚点仍在 `References:` 行里按内容顺序标注。角色的锚点是 `video_asset_images` 在纯色背景上生成的正面半身定妆照，或用户提供的照片；这张单张正面图也正是 image API 文档对角色条件的要求。

定妆照与母图是同一套设计。`video_asset_images` 先生成定妆照，再以它为 `subject_reference` 条件生成母图——正面、侧面、背面三视图加面部大头照——因此各视图之间不会在发型、五官、服装、配饰或体型比例上漂移。定妆照是每个关键帧所依据的条件锚点；母图是展示给用户、并随素材一起保存的设计记录。

素材会持久保留，措辞也固定。记录素材会把它写进 `outputDir/assets/library.json`，带上参考图、母图和一个规范 `prompt` 块；generation 看到的是这个块（而不是面向人的简短 `description`），它会原样复制进定妆照、母图、每个关键帧与每个片段，因此只有人改写它时措辞才会变。`video_plan library_assets` 按名称或 id 挂载已保存的素材，`video_library` 列出库中内容，因此后续剧集复用同一批演员，而不是重新定义。

关键帧带上角色。镜头点名某个已锚定角色时，`video_keyframes` 会把该角色的定妆照作为 image API 的 `subject_reference` 发送，因此静帧在任何运动采样之前就呈现确认过的角色；视频随后从这张静帧出发（首帧条件）或保留参考素材集。本地参考路径会内联为 base64 data URI；API 公布的限制（单个角色、PNG/JPEG、小于 10 MB）会在提交前响亮失败。两个静帧工具都接受种子覆盖，`video_asset_images` 还接受 `regenerate`，因此已确认的定妆照或关键帧可复现，被否掉的那张可以重掷而不打扰其余部分。

每个计划一个种子。`video_plan` 接受可选的 `seed`；省略时计划用自己的 id 与创建时间推导一个并写进计划文档。种子在修订之间保留、出现在每次计划结果中，并填入本地 ComfyUI workflow 的 seed 占位符，因此重渲染同一镜头会采样同样的噪声。托管 H3 API 没有 seed 参数，会忽略它。

## Alternatives considered

- **靠 `multi_shot` 保证一致性。** 否决：一条 H3 任务受 15 秒上限约束，需要多个镜头的影片用不了。
- **把每个锚点素材都挂到每个镜头。** 否决：单个角色的镜头会带着其余角色与全部场景作为参考，把生成拉向画面里并不存在的元素。定向匹配让参考集等于 prompt 点名的内容。
- **把上一个镜头的末帧接到下一个镜头的首帧。** 暂缓：那是运动连续性，不是静态一致性。它会取消剪辑点、需要顺序渲染加抽帧步骤，对本来就要在镜头之间剪辑的影片没有帮助。
- **关键帧只按文本生成。** 否决：这正是本记录要修的缺陷。纯文本静帧会发明一张脸，视频则忠实地复现这张错的脸。
- **继续用四视图设定图作为角色锚点。** 否决：image API 的 `subject_reference` 检测的是单人正面图，而设定图里那个人只占四分之一画面。锚点改成专为条件生成的正脸定妆照，母图则由定妆照生成供审阅；用户自己提供的照片仍然优先，因为那是最强的参考。
- **每个计划重新定义素材。** 否决：按计划维护的演员会让每一集重新生成角色，而项目资产库正是为了消除这种漂移。库以素材名为键，再次记录同一素材时就地更新。
- **把素材图生成为关键帧（图生图）。** 否决：image API 把角色条件暴露为 `subject_reference`，而不是图生图的强度参数。

## Consequences

- prompt 会增加每个挂载素材的描述与一行风格；锚点较多的计划每段多花一些 prompt 字符，受既有 prompt 上限约束。
- prompt 点名了锚点的镜头只以点名的那些为条件；从不点名锚点的分镜以全部锚点为条件，每段仍会带上计划风格与种子。
- 关键帧现在依赖 image API 的角色参考，而这个参考是素材工具产出的正面定妆照。之所以用生成的单张正面照而不是多视图设定图，是因为 API 文档表明它检测的是单人正面图；母图随后由定妆照生成。
- 角色设定要花两次生图（先定妆照，再母图），场景与道具仍是一次。
- 资产库位于 `outputDir/assets/library.json`，随配置的输出目录走：换 `outputDir` 就等于换一个库，同名素材再次记录会覆盖旧记录。
- 计划文档携带可选的 `seed`；没有种子的计划每次提交抽随机种子，因此每次渲染都采样新的噪声。
- 种子只作用于本地。托管渲染的采样仍不可复现，但 prompt、参考素材与关键帧依然承载观感。
