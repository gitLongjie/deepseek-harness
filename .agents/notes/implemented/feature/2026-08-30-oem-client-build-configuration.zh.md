# Agent Note: OEM 客户端构建配置

Status: implemented

[English](2026-08-30-oem-client-build-configuration.md) | 中文

## 问题

浏览器产品名称、品牌图片、登录端点、桌面更新源、本地化登录副标题与分时空面板文案分别由 Vite、Electron、插件、locale 和组件文件持有。一次 OEM 构建因此需要协调修改多处源码，还可能编译出身份或更新目标不一致的产物。

## 决策

仓库根目录的 `oem.config.json` 是 `productName`、`brandIcon`、`loginUrl`、`updateUrl`、中英文 `loginTagline` 值及两种语言五段问候语的编写来源。`brandIcon` 指向 `apps/web/public` 下一个根相对 `.ico` 文件，`updateUrl` 指向存放 electron-updater 频道元数据和发布产物的 HTTPS 目录。`scripts/oem-config.ts` 会校验精确字段集、必填字符串、本地 ICO 路径、HTTPS 端点、登录副标题与完整问候语字典，然后将浏览器持有的值投影为 `DSH_CLIENT_*` 构建值。

Vite 与动态客户端 tsdown preset 读取同一份已校验文件。Vite 会把配置的名称与图标投影到初始 HTML 和解析后的 Web App Manifest。完整根构建通过既有客户端构建环境传递这些投影值，因此构建记录仍会把所有公开值同时绑定到两类产物。显式提供的 OEM `DSH_CLIENT_*` 值可为单次构建覆盖文件；空登录 URL 覆盖继续保留受支持的编译排除行为。

桌面开发启动器会在 Vite 消费客户端 tsdown 产物前重新构建这些产物，因此 `pnpm run dev` 无需单独构建客户端即可反映当前 OEM 文件。开发与打包流程会在 Electron 消费图标前把配置的公共 ICO 复制到桌面应用和托盘图标位置。渲染器标题栏读取 Vite 投影后的 favicon 链接，开发可执行文件嵌入同步后的应用图标，electron-builder 也会打包同一图标。启动器会把 `productName` 和 `updateUrl` 传给 Electron 主进程。桌面打包流程会生成携带产品名称和更新 URL 的 electron-builder 覆盖配置；打包后的主进程从 Electron 应用名称与包元数据读取这些值。更新器会在启动检查或手动检查之前根据 `updateUrl` 配置 generic feed。

仅支持 Windows 的 `test:update:local` 命令会把显式指定版本的基线和更新分别构建到不同的忽略目录，无需编辑 manifest；它会校验频道元数据及引用文件，必要时复现 publisher 使用的安全产物名，并通过回环接口提供支持字节范围请求的更新目录。开发环境可以从工作区解析仅供运行时使用的 Service Definition 包与已配置的本地 IM 插件，而 electron-builder 只会打包已声明的生产依赖图，因此桌面部署 manifest 会显式提供这些包。其私有打包环境会把继承的 publisher 替换为 generic 回环 feed，并把类型严格的布尔演练标记写入包元数据。仅当该标记存在且选定 URL 指向 `127.0.0.1`、`localhost` 或 `[::1]` 时，运行时才接受 HTTP。其他所有打包路径都会拒绝非 HTTPS 更新 URL，而且除非发布命令显式要求上传，否则都会传入 `--publish never`。

无框架桌面渲染器在标题栏专用槽位中提供本地化更新控件。主进程根据已安装版本的 prerelease 标识派生 generic metadata 频道，例如 `1.0.0-local.1` 使用 `local.yml`，并把更新器失败写入持久桌面日志。它通过更新器 IPC 频道发布检查中、可用、字节进度、已下载、安装中、空闲与错误状态。启动检查只通过标题栏控件报告可用版本；显式菜单检查会针对发现版本、当前最新版与检查失败显示本地化弹窗。在可用版本弹窗中确认会开始同一个带进度报告的下载，选择稍后则保留标题栏操作。发现可用更新后，也可以通过标题栏控件直接开始下载；下载期间会禁用重复操作并显示经过范围限制的百分比。安装包下载完成后会打开本地化重启弹窗。确认后，控件会被禁用并显示安装器启动状态，共享退出控制器会先清理应用树，然后 electron-updater 才以可见模式启动原生安装器。准备阶段只执行一次清理，最多等待五秒且不会自行退出；更新器触发的 `before-quit` 随后会跳过常规清理拦截，因此清理超时也不会让 NSIS 再与另一个五秒退出流程竞争。选择稍后会保留重启操作，主进程每次运行只接受一次安装操作。检查失败后会提供重试，无可用更新时会移除控件。主进程校验由检查、下载和安装组成的闭合操作集，再调用 electron-updater。

品牌、登录、启动页与 Conversation 包只静态读取该环境的属性。Locale 字典仍然拥有产品文案：Conversation 插件仅在注册前替换五个类型化问候语键，登录插件则根据配置的产品名称派生本地化页面标题，并以当前语言的配置值替换副标题。登录卡片与其他品牌界面使用同一个配置的 `brandIcon`。

## 考虑过的替代方案

**让每个客户端包直接导入 JSON。** 未采用，因为动态插件 bundle 与 Vite 外壳使用不同构建图和发布根。直接导入会重复解析，还可能让仓库相对文件落在包的发布闭包之外。

**由 Host 在运行时提供品牌配置。** 未采用，因为 favicon、初始 document title 与无框架启动页必须在客户端插件树连接前就正确显示。OEM 身份属于产物内容，只在应用重新构建时变化。

**继续以独立环境变量作为主要入口。** 未采用，因为 OEM 发布仍需协调多个构建输入。环境变量保留为单次构建的窄覆盖方式，版本化 JSON 文件则提供默认值。

**分别配置 Web、应用与托盘图标字段。** 未采用，因为独立维护的文件即使发生偏差仍可能成功构建。一个 ICO 源文件会复制到每个原生图标位置，并直接嵌入全部 Web 消费位置。

**要求更新演练使用受信任的本地 HTTPS 证书。** 未采用，因为创建证书和修改信任存储会引入与更新器行为无关的主机状态。演练把显式 HTTP 例外限制在回环主机和包元数据内的类型严格标记；生产配置仍仅允许 HTTPS。

## 后果

修改一份 JSON 即可在同一次构建中更新浏览器标题和 favicon、Web App Manifest、品牌槽位、登录端点、更新源、图标与本地化副标题、全部分时 Hero 问候语、桌面原生窗口与托盘标签和图标、“关于”文案及打包产品身份。非法 OEM 字段会在产生部分产物前停止构建。配置的品牌图标必须是 `apps/web/public` 下的本地 `.ico` 文件；远程及非 ICO 图片会被拒绝，因为 Electron 的 Windows 可执行文件资源需要 ICO 数据。更新 URL 必须使用 HTTPS，并提供 electron-updater 元数据及匹配的产物。该配置会进入公开产物，绝不能包含凭证。维护者无需发布 release 或修改编写版本，即可在本地演练打包应用的更新发现、可见下载进度、差分下载、重启确认与可见原生安装。
