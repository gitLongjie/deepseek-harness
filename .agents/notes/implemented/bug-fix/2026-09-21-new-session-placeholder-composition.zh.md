# Agent Note: The New Session placeholder keeps the composition a new Session gets

Status: implemented

[English](2026-09-21-new-session-placeholder-composition.md) | 中文

## Problem

工作区的空白会话就是该工作区的「新会话」占位会话：`uiWorkspace.connectWorkspace` 在之后每次新建会话流程中都会复用它。它也带着此前某个流程给它的组装，而聘用专家正是这样一个流程——专家页暂存该专家并启动一个会话，于是复用了这个占位会话、把专家组装进其中。之后每次点「新会话」都会接管同一个会话，下一个对话就以没人选择过的组装开始，而第一条消息到达时组装即被固定。composer 旁的芯片还让这个报告更难读：它只从自己的选项里取名，而选项排除了专家标记行（`presetOptions`），因此运行专家的对话要么只显示一个裸标识符，要么根本没有名字。报告该问题的机器上 `agent-presets.default` 是 `standard`，而被接管的空白会话记录的是 `geo-optimizer`。

## Decision

`UiWorkspace.bindPlaceholderAdoption(listener)` 在工作区导航服务上注册一步：`connectWorkspace` 每接管一个空白会话，就在该次 connect 返回之前执行这一步；某一步抛错也绝不会让导航失败。这一步做什么由预设域拥有。`AgentPresetSeatController.prepareNewSession` 恢复名单中被标记的默认值——也就是 `session.create` 会解析出的那个组装——但只在这些界面不可能选择过当前组装时才恢复：芯片或设置页提供的模式属于该流程自己的答案，保持不动；而没有任何菜单行可对应的组装（从市场聘入的专家、此后被删除的预设，或根本没有记录过预设）才是别的流程留下的残留。本流程已经暂存了选择时立即返回，因为把会话切换到它是 applier 的职责。本包自己创建的会话天然就组合同一个默认值，因此这一步只对被接管的占位会话执行。

芯片改为在整份健康名单上命名一个对话所运行的组装（`AgentPresetSeatState.currentPreset`），而不只在自己提供的选项里找。聘用专家的对话显示该专家发布的名称，并用提示说明该对话由它组装；已经没有任何健康行可对应的预设（此后被删除或损坏）显示其标识符，并用提示说明它当前不可用。菜单仍然只提供模式。

## Alternatives considered

**只要占位会话的组装与默认值不同就恢复。** 否决：这会撤销用户为这个对话做出的选择——在芯片上选了「极简模式」再点「新会话」，对话会被悄悄改回默认模式；选择后刷新页面同样如此。

**在 `connectWorkspace` 里比较组装，不同就新建一个会话。** 否决：空白会话就是工作区的占位会话、也是该流程对「开始新对话」自己的答案，丢弃它会留下一个游离的空白行，并让每次新建会话流程都付出一次会话创建的代价——而它持有的组装并不是本包能判断的事实。

**由工作区层返回被接管会话的预设，再让会话区去切换。** 否决：一个决定被拆到两个包里，还要让工作区层去决定组装——那是预设域的词汇——并在已拥有此事的暂存选择之外再造第二条切换路径。

**像模式界面那样，把专家标记的预设排除在复用之外。** 否决：同一个缺陷只是宽了一行。留在占位会话上的自建预设仍会泄漏，而这条规则会变成 `presetOptions` 与市场之外的第三处。

**芯片仍只从自己的选项取名，让专家对话显示标识符。** 否决：那种读法正是这次报告本身。运行专家的对话必须说出来，而它的名称只存在于专家市场。

**让 `ui-workspace` 依赖预设界面。** 否决：本包拥有导航与占位会话的生命周期，而不是「组装是什么」；该钩子把组装的决定留在读取名单的那个插件里，而 `ui-agent-preset` 本就为启动会话声明了 `uiWorkspace`。

## Consequences

在被聘用留下组装的工作区上，「新会话」会以它承诺的组装开始对话；芯片也会写明下一个对话将运行的组装，包括专家。当被接管的占位会话的组装不是默认值、且本流程自己的界面不可能选择它时，这一步会多花一次 `agentPresets/select` 往返；已经是默认值、或属于本流程界面可选范围时一次也不花。名单没有标记默认值时什么都不恢复，因为新建会话本来就不会产生任何组装。工作区导航服务现在持有一份注册，因此其 README 也如此陈述，而不再声称不持有跨插件可变状态。

## Testing

`settings-store.client.spec.ts` 固定恢复动作与每一种跳过——已开始的会话、本流程已暂存的选择、芯片可提供的模式、名单未标记默认值、名单读取被拒，以及会话在步骤执行中开始而返回的拒绝——并固定对未记录任何预设的占位会话的恢复，以及芯片命名菜单无法提供的专家。`apply.client.spec.ts` 固定会话作用域注册的绑定、恢复动作经 `agentPresets/select` 到达宿主，以及芯片命名聘用专家的对话。`workspaces-service.client.spec.ts` 固定只对被接管会话注册、解绑，以及在步骤失败时仍然完成的导航。`components.client.spec.tsx` 固定芯片的标签，以及面向专家、面向无任何行对应的标识符、面向被拒切换三种提示。
