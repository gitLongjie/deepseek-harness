# Agent Note：专家预设不再出现在模式表面

Status: implemented

[English](2026-09-19-expert-presets-stay-out-of-mode-surfaces.md) | 中文

## 问题

桌面端把深度云海文章专家与 GEO 优化专家作为内置 agent preset 随附，已安装的专家包又会把同样的 preset 同步进用户预设根目录。于是每个名单表面都提供这两位专家：新会话预设选择器、设置里的预设管理区、专家页。专家页早已只收录发布了卡片元数据的行，但反方向的规则缺失，专家就这样以模式预设的身份与各模式并列——而且选择器可以据其开会话，而其文件会被已安装专家包的挂载插件在每次宿主启动时重新同步。

## 决策

`preset.yml` 中的 `category` 是既定的专家标记，现在由一个共享谓词——从 `@deepseek-ai/dsh-agent-presets/display` 导出的 `isExpertPreset`，每个客户端 bundle 都可内联的 inline-safe 纯折叠——同时拥有这条规则的两个方向。新会话芯片（`presetOptions`）与预设管理区排除专家标记的行；专家页只收录它们，替换原先内联的 `category` 过滤；会话头部标签保留全部健康行（`presetDisplayEntries`），因为它要为已经在运行专家的会话显示名称。当生效默认值带专家标记时，芯片的初始值回落到第一个可提供的模式；名单只剩专家时，管理区渲染为不可用。线路上的行不变：区分只在展示层，宿主投影仍是唯一事实源，聘用继续按 id 解析 preset。

## 考虑过的替代方案

**在宿主的 `agentPresets/list` 投影中过滤。** 四个表面的诉求相互冲突——专家页需要专家行，标签需要它们的名称——服务端拆分要么把发现过程复制成两个 face，要么用参数把行重新暴露一遍，都只是为了把一次 `filter` 挪过网络。

**让专家保留在设置管理区，逐个动作加限制。** 随附专家的包会在每次宿主启动时重新同步其文件，在这里查看、复制或删除同步来的行，等于许诺了包自己拥有的管理权；桌面端可见的那行还是系统信任的内置预设，删除本来就会拒绝。

**经由 ui-agent-preset 的客户端入口共享谓词。** 客户端打包纯度门禁拒绝一切既非声明模块表行、也非 inline-safe 折叠的跨插件值导入，而仅类型导入会在抵达浏览器前被擦除——所以谓词的家必须自身 inline-safe，也就是预设域的 `display` 折叠。

## 后果

专家只从专家页进入；选择器与管理区只列模式预设，标签仍为聘用了专家的会话显示名称。已安装专家包同步到用户根目录的副本在预设表面不再有删除入口——该删除归市场安装通道的卸载工作所有，桌面端本就如此（可见行从未可删）。`settings-store.client.spec.ts` 与 `section-store.client.spec.ts` 钉住了排除规则、标签的保留规则，以及纯专家名单的不可用状态。
