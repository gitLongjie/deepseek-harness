# Agent Note: 视频片段之间的平滑转场

Status: implemented

[English](2026-10-21-video-assembly-crossfade.md) | 中文

## Problem

逐段拼接默认用硬切连接独立生成的片段。此前的淡黑实现要求每段都有音轨，且在失败时静默改为硬切。因此，用户要求平滑转场后，交付的成片仍可能突然切换。

## Decision

`video_assemble` 将省略的转场解析为 `crossfade`，每次调用可调整重叠时长，默认为 0.4 秒。`cut` 仍可显式选择，`dip` 保留默认 0.25 秒的半段转场时长。底层服务对其他消费者仍默认直接拼接。多镜头模式原样返回已经合成的片段，不再施加转场。

转场拼接使用指定 ffmpeg 同目录或 PATH 中的 ffprobe 检测视频尺寸与音轨。视频统一为第一段的尺寸及 24 fps，以补边保持比例；音频统一为 48 kHz 双声道，无音轨时补静音。每段按提供的计划时长裁切或补足。交叉淡化使用 `xfade` 混合画面、`acrossfade` 混合声音，每次重叠不超过任一相邻片段时长的一半。淡黑先处理每段的淡入淡出再拼接。时长非法或处理失败时直接报错，不会退回硬切。

拼接结果允许小数秒，并从计划总时长中扣除交叉淡化的重叠部分。计划文件与 Session 事件字段不变。

## Alternatives considered

**所有连接均淡黑。** 淡黑会在镜头之间形成停顿。交叉淡化提供用户要求的画面重叠且不插入黑场；换场仍可选择淡黑。

**用首尾帧串联重新生成全部片段。** 生成连续性处理画面和动作差异，不能替代用户要求的剪辑转场，还会增加渲染成本。

**转场失败后返回硬切。** 这会隐藏缺失的效果。现在调用者收到错误后，可显式选择硬切。

## Consequences

已有片段可直接重新拼接，无需重新生成。交叉淡化会重叠音频，也可能重叠连接处的对白；对白节奏需要时应缩短转场或选择硬切。转场处理需要 ffprobe，并重新编码视频。本操作不会改变单条多镜头视频中已经生成的内部切换。

真实 ffmpeg 测试检查连续连接点解码后的像素、淡化期间音量、时长、静音输入、不同帧率与尺寸，以及重叠上限。真实 Loader 组合调用面向模型的拼接工具，并通过工作台读取产物。包内 schema 快照固定模型可见的转场选项；该场景使用生成的媒体文件，不回放录制的 Session。
