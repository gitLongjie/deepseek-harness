# Agent Note: 启动改为复核已存密钥，不再新建登录会话

Status: implemented

[English](2026-10-20-ui-login-key-revalidation.md) | 中文

## 问题

登录网关在每次启动时都会重新登录：`restore()` 把存储的账号密码对重放到 `POST /api/claw/login`。在 Deepagens Claw 网关上，这次调用会创建一个服务端登录会话，而网关对单个账号可持有的登录会话数量与新建速率都设了上限。一个每次启动都登录的桌面应用因此花掉的是为交互设备准备的预算：2026-10-20 该账号在 10:01 与 10:08 登录成功，从 10:49 起被拒，返回 `{"message":"failed to create login session","success":false}`——HTTP 200 的响应体，唯一的问题在于网关不愿再开一个会话。凭据、网络与网关本身都正常，是客户端自己把会话用光了。

也没有任何东西回收这些会话。登录响应不携带会话令牌，退出登录只清理本地状态，客户端也没有可撤销服务端会话的调用，于是每次启动都净增一个。

## 决定

启动时通过复核上次登录签发的密钥来恢复会话，只有该密钥失效时才调用登录端点。

`restore()` 读取同一条存储记录，并用其中的密钥请求 `GET {登录源}/v1/models`。密钥被接受则进入应用：通过登录所用的同一凭据适配器把密钥写入 `DEEPAGENS_API_KEY`，网关目录同步照常在该密钥上运行，账号行用存储的资料渲染。密钥被拒——吊销、过期、额度耗尽——以及任何触达不到网关的探测，都会落到账号密码对重放：那是唯一会创建登录会话、也是唯一能更换密钥的路径。本次改动之前写入的记录没有密钥，会重放一次并补上。

存储记录保留原有 `localStorage` 键（`dsh.login.pair`），并新增三个可选字段——签发的 `apiKey`、上报的 `account` 与 `avatar`——使升级后的构建保留静默登录，而不是强制手动登录一次。

## 备选方案

**每次启动仍登录，登录后再撤销会话。** 登录响应不携带会话标识或令牌，该端点也没有撤销调用，浏览器端无法释放自己创建的会话。

**每次启动仍登录，被拒后退避。** 仍然每次启动创建一个会话，最终仍撞上同一把锁；退避只是把失败推后。

**取消静默登录，每次启动都显示登录卡片。** 满足"不用过期密钥"的目标，但每次启动都要输入密码，而这正是账号密码对重放要避免的行为。

**放宽或关闭网关的登录会话上限。** 网关是仓库之外、由部署方拥有的 new-api 服务；要求服务端放宽限制才能让客户端工作，掩盖的是客户端自己的消耗。

**只存密钥、不存账号密码对。** 密钥被吊销时用户每次启动都会卡在卡片上且无法自动恢复，改密码也只能靠手动发现。

## 后果

- 普通启动的代价从一次登录会话变为一次带鉴权的模型列表读取，网关按账号计算的会话预算不再被"开应用"消耗。
- 被吊销、过期或额度耗尽的密钥仍会在启动时被发现并替换，这正是引入账号密码对重放所要保住的性质（[启动时账号密码对重放](2026-09-25-ui-login-launch-time-pair-replay.zh.md)）。
- 存储记录现在会在 `localStorage` 中保留签发的密钥与资料，与明文账号密码对并列；两者都留在渲染进程的用户配置里。
- 服务器端改名或换头像要等下次账号密码对重放才会出现，密钥复核不会刷新它。
- 已经撞到网关上限的账号，下一次启动仍会被拒——重放本身仍需要一个新会话——直到滚动窗口过去或在网关上撤销旧会话。

## 测试

`LoginStore` 的恢复套件固定了各条路径：密钥被接受时只做一次模型列表读取、不产生登录 `POST`；密钥被拒时重放账号密码对并存入新签发的密钥；探测触达不到网关时回退到重放；无密钥的记录重放一次；账号密码对被拒时保留记录并把服务器消息交给卡片。登录套件固定了成功登录写入的记录，以及退出登录会清除它。
