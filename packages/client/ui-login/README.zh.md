# @deepseek-ai/dsh-client-ui-login

[English](README.md) | 中文

## 概述

本包针对部署的账号服务器注册登录流程。仓库 [`oem.config.json`](../../../oem.config.json) 提供默认端点、产品名称、共用的 `brandIcon` 及中英文 `loginTagline` 文案。登录卡片会渲染该图标与当前 locale 的副标题；显式的 `DSH_CLIENT_LOGIN_URL` 会覆盖端点，将它设为空字符串的构建只加载插件、不注册任何占位。

## 目录

三个占位通过声明感知的 `slots.inject()` 安装，因此与 ui-layout、ui-settings 的激活顺序无关，卸载时一并撤出：

- `shell.overlay` —— 整页登录接管（品牌标、用户名/密码表单含密码显隐切换、服务器消息原文展示）。遮罩自行恢复指针事件，因为 overlay 层本身设计为点击穿透；遮罩还遵守桌面壳层发布的顶部保留区，使窗口标题栏保持可用。启动会话恢复进行中时只渲染遮罩；已登录时不渲染任何内容。
- `settings.launcher` —— 已登录账号启动器，以 `priority: -1` 注册，因此在同时载入两者的组合中遮蔽上游的 `AccountMenu`：头像（缺失时以首字母回退）与宽栏模式下的昵称点击后打开含退出登录的下拉菜单，旁的齿轮按钮通过该占位的 `openSettings` 打开设置面板。
- `settings.section` —— 网关会话的设置「账号与余额」页，以上游 section 的 `id`（`account`）、`priority: -1` 注册，与启动器同理遮蔽上游的 DeepSeek 账号页，且仅在网关会话存续期间生效。页面渲染账号身份与已用、剩余 token 数（见下文「Token 额度」）；「控制台」与「充值」链接指向网关 origin 的控制台。

登录成功（线上契约：`POST {username, password}` → `{success, message?, data: {display_name?, avatar?, api_key}}`）后，会话保存在内存中，键入的账号密码对、签发的密钥与资料存入 `localStorage`，并通过既有的 `credentials.set` 线上方法把网关密钥写入 `DEEPAGENS_API_KEY`——与模型设置页使用的同一可写层，但使用网关路由自己的引用。`DEEPSEEK_API_KEY` 刻意不动：它属于 DeepSeek 路由，而每次启动的重登录若写入它，就会覆盖用户在该处保存的密钥。网关端点不需要凭据条目，因为目录同步会把地址写进该路由的 `llm-deepagens` 设置段。写入被拒绝时登录响亮中止。退出登录只取消 `DEEPAGENS_API_KEY` 并清除存储的登录记录，其余已存凭据保持不动。

## Token 额度

已登录密钥的 token 额度从 new-api 系网关的令牌用量端点读取，以会话密钥为 Bearer 凭据：`GET /api/usage/token/` 的 `data.total_used` 是已使用 token 数，`data.total_available` 是剩余 token 数。这两个数是网关的 token 额度，不是显示美元。`data.unlimited_quota` 为 true 时密钥不设剩余上限，页面显示不限额而不是剩余数字。每次登录与每次启动时的会话采纳会安排一次读取；网关账号页在每次进入设置时重读。重读失败保留上一次的好值而不降级；首次读取失败提供重试入口；读取进行中退出登录则丢弃过期结果。

每次启动都会在界面定着前用一次 `GET /v1/models` 复核存储的密钥。密钥被接受则直接进入主界面、不显示登录卡片，也不发出账号服务器会计收一次登录会话的 `POST`；目录同步仍在该密钥上运行。密钥被拒（吊销、过期、额度耗尽）则用存储的账号密码对重放登录端点，并存入该次登录签发的新密钥。账号密码对被拒时保留记录供下次启动重试，并回退到登录卡片、展示失败原因；键重用之前写入的记录（只有账号密码对、没有密钥）会重放一次并补上密钥。

端点必须允许来自应用源的跨域调用（带 JSON content-type 的 CORS）；fetch 失败路径报告服务不可达而不是破坏页面。

模型设置页的 Deepagens 卡片提供"跟随登录网关的模型目录"开关，对应 `llm-deepagens` 的 `followGatewayCatalog` 字段（默认开启）。显式设为 `false` 后路由交还用户管理：登录不再改写 `baseURL`、替换 `models`、写入 `imageModel`、接管默认模型，卡片上的手工配置在每次启动的目录同步中得以保留。跟随开启时，`supported_endpoint_types` 含 `image-generation` 的目录行会以 `endpoint: image-generation` 存储，且不会被接管为默认对话模型。登录会让 `imageModel` 指向带该标签的模型：已存的带标签 id 保留，其他值替换为第一个带标签的 id；目录中没有带标签的模型时，保留已存 id，或写入 `gpt-image-2`（内置基础组合的默认值）。

## 模型体验

间接地，通过登录写入的设置命名空间：拉取的网关目录落入 `llm-miaoworker` 提供商设置（独立选择器分组），拉取目录不包含的默认模型会在 `agent-default-model` 中被重新指向其第一个模型；本包自身从不组装提供商请求。存储的登录会话若记录的来源 origin 与本构建的登录端点不一致（部署迁移过，或会话早于 origin 记录字段），启动时会做尽力重播种：重写凭据对并按当前端点重新拉取目录。

#### KV Cache 影响

默认模型采纳发生在任何会话存在之前，因此它改变的是首个会话组装哪条路由，而不是任何请求的内容；后续的手动选择自行承担各自的缓存影响。

## 已知限制与后续工作

- **不刷新会话** —— 资料仅用于展示；服务器端改名或换头像要等下次账号密码对重放（密钥被拒或手动登录）后才会出现，密钥复核不会刷新它。
- **无注册入口** —— 账号由账号服务器发放；登录卡片刻意不提供注册链接。
- **不代发会话请求** —— 本包不将账号服务器的 session cookie 重放到其他端点。

### 开发备注

三个占位观察同一份内存会话存储；退出登录置空一次会话即可同时撤出三个表面。`localStorage` 中存储的登录记录服务启动时的密钥复核及其后的账号密码对重放——会话本身从不持久化。
